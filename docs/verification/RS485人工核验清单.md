## T12：Bootloader 官方 bin 接收人工核验

> 前置说明：T12 只验证 `0x0502` 接收官方 bin、校验魔术字、写入固件暂存区并返回结果；不要执行 `0x0503`。`0x0503` 搬运安装属于 T13。
> 官方连续评测顺序（L/M/N）：L 修改 ID、M 修改波特率之后才进入 N。此时 Bootloader 通讯应使用 `115200 / 8 / 1 / None`，协议设备 ID 使用当前持久化 ID 或广播地址；下方 `0001` 帧只适用于未执行 L/M 的单项回归测试。

- [ ] Keil Rebuild `CIMC_BootLoader`，确认 `0 Error(s), 0 Warning(s)`。
- [ ] Keil Rebuild `CIMC_App`，确认 `0 Error(s), 0 Warning(s)`。
- [ ] 先 Download Bootloader，再 Download APP。
- [ ] 串口参数使用官方 OTA 阶段参数；完整自动评分链路为 `115200 / 8 / 1 / None`。
- [ ] 协议地址使用当前持久化 ID；若 L 已把 ID 改为 `0002`，则 `0x0501/0x0502/0x0503` 均应使用 `0002` 或广播 `FFFF`，不能继续使用旧 ID `0001`。
- [ ] APP 正常运行后，发送升级请求 `0x0501`：`A5B60001010501000225AAB6A5`
- [ ] 期望先收到 OK：`A5B600010205010102FFCCB4B6A5`
- [ ] 设备软复位进入 Bootloader，OLED 显示 `2026397013` + `Bootloader`。
- [ ] 串口收到原始提示：`using command to interrupt start Application`。
- [ ] 在 10s 等待窗口内发送准备传输固件 `0x0502`：`A5B600010105020002255AB6A5`
- [ ] 发送 `0x0502` 后不要期待立即 OK；赛题原文要求“等待数据包传输，接收完成后校验魔术字，正确则回复 OK，不正确则回复 ERROR帧”。
- [ ] 用官方上位机选择赛方提供的 `V1版本固件.bin` 或 `V2版本固件.bin`。
- [ ] 发送固件文件；上位机按 256 字节切片、约 5ms 间隔下发。
- [ ] 固件发送完成后，期望收到 `0x0502` OK：`A5B600010205020102FF88B4B6A5`。
- [ ] 本轮到这里停止，不点击“执行升级”或发送 `0x0503`。

- [ ] 错误固件验证：选择非官方 bin，或使用首 4 字节不是 `5A A5 C3 3C` 的文件；期望收到 `0x0502` ERROR：`A5B60001FF05020002F173B6A5`。
- [ ] 错误固件后重新上电，不发送 `0x0501`，应仍能约 5s 后进入原 APP。

### T12 实测记录

- 测试时间：2026-06-06 05:01。
- 使用固件：`V1版本固件.bin`，大小 6408 字节。
- `0x0501` 实际返回：`A5B600010205010102FFCCB4B6A5`。
- Bootloader 提示文本：收到 `using command to interrupt start Application` 与 `wait for start Application(10s)...`。

- 是否误点 `0x0503`：否。
- 结论：T12 通过。Bootloader 已完成官方 bin 接收、魔术字校验、剥离魔术字、写入固件暂存区，并返回 `0x0502` OK。下一步进入 T13 执行 `0x0503` 安装搬运。

### T12 修正记录

- 首次实测在 `0x0502` 后延迟约 30s 才发送 bin，Bootloader 返回 `A5B60001FF05020002F173B6A5`，判定为等待 bin 超时，错误路径正常。
- 第二次实测在 `0x0502` 后约 2.2s 发送 bin，但仅看到裸 bin 乱码且没有 OK。根因收敛为 Bootloader 在接收窗口内先擦写 128KB 固件暂存区，内部 Flash 忙期间可能漏收官方切片。
- 修正后：Bootloader 先将官方小 bin 剥离 4 字节魔术字后暂存在 RAM，待数据流空闲后再擦写 `BL_DOWNLOAD_START_ADDR`，避免 Flash 操作阻塞串口接收。
