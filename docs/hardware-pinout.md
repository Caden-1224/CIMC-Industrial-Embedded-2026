# GD32F470 开发板引脚分配建议

## 1. 文档目标

本文档用于给 `CIMC_GD32F470 Development Kit V2.0` 提供一份面向比赛开发的、可直接落地的引脚分配建议。

目标不是单纯把空闲 GPIO 填满，而是先明确以下三件事：

- 哪些引脚已经被开发板板载资源固定占用。
- 哪些引脚属于系统关键资源，原则上必须保留。
- 哪些引脚适合通过跳线分配给用户按键、用户 LED、扩展通信和后续决赛外设。

这份建议覆盖的功能范围与样题要求保持一致：

- ADC 数据采集
- DAC 模拟输出
- OLED 显示
- GPIO 按键输入
- GPIO LED 状态指示
- 串口通信
- RTC
- 外部 Flash 读写
- 低功耗唤醒
- Bootloader 基础功能
- 决赛阶段外接 SPI ADC 的扩展预留

## 2. 结论摘要

这块板最合理的规划方式不是重新发明接口，而是最大化复用板载资源：

- `PA9 / PA10` 固定作为主调试串口。
- `PB8 / PB9` 固定作为板载 `OLED + EEPROM` 的 I2C 总线。
- `PA15 + PB3 / PB4 / PB5` 固定作为板载 SPI Flash。
- `PC0` 固定作为当前阶段最优 ADC 输入。
- `PA4 / PA5` 优先保留给 DAC，不再建议用于最终 LED。
- `PA0` 固定作为唤醒按键和低功耗恢复入口。
- `PD10 ~ PD15` 最适合作为 6 路用户按键输入。
- `PE0 / PE1 / PE3 / PE4 / PE5 / PE6` 最适合作为 6 路用户 LED 输出。
- `PE12 / PE13 / PE14 + PE10` 预留给决赛阶段的外接 SPI ADC。

该方案的核心思想是：

- 系统关键脚不碰
- 板载固定资源直接复用
- 用户键灯集中落在连续、干净、易管理的 GPIO 上
- 保留后续决赛扩展空间

## 4. 引脚规划原则

### 4.1 系统关键资源优先保留

以下引脚属于系统级关键资源，不应随意分配给普通业务功能：

- `PA13 / PA14`：SWD 下载与调试
- `NRST`：硬件复位
- `BOOT0 / PB2(BOOT1)`：启动模式选择
- `PC14 / PC15`：RTC 32.768 kHz 晶振

原因：

- 这些引脚决定了程序是否还能下载、调试、复位和可靠启动。
- 比赛开发周期紧，失去 SWD 和正常启动链路会显著增加排障成本。

### 4.2 板载固定连线资源优先复用

开发板已经把部分资源直接接到了 MCU 上，这些资源不应重复规划：

- `PB8 / PB9`：OLED 与 EEPROM 共用 I2C
- `PA15 + PB3 / PB4 / PB5`：板载 SPI Flash
- `PC0`：板载电位器 ADC 输入
- `PA0`：板载 `WK_UP` 按键
- `PA9 / PA10`：通过 `H12` 接 `CH340`
- `PD5 / PD6 + PE8`：通过 `H10` 接 RS232 / RS485
- `PD8 / PD9`：通过 `H11` 接 TTL / 通信扩展

原因：

- 这些连线是板卡设计时就已经决定好的资源路径。
- 复用这些路径可以显著减少硬件接线工作量和调试复杂度。

### 4.3 用户自定义资源集中分组

用户 LED 和用户按键虽然板上各有 6 路，但它们并没有焊死到固定 GPIO，而是通过跳线帽选择。

因此在规划时应优先选择：

- 引脚连续
- 所属 GPIO 组集中
- 不与关键外设冲突
- 后续做中断、扫描或统一初始化方便

## 5. 板载资源梳理

### 5.1 固定占用或强相关资源

| GPIO | 板载资源 | 建议状态 | 原因 |
|---|---|---|---|
| `PA0` | `WK_UP` 按键 | 固定保留 | 低功耗唤醒入口，同时可兼作模式按键 |
| `PA1` | `ETH_REF_CLK` | 不建议占用 | 以太网 RMII 时钟关键脚 |
| `PA2` | `ETH_MDIO` | 不建议占用 | PHY 配置链路 |
| `PA7` | `ETH_CRS_DV` | 不建议占用 | RMII 接收有效信号 |
| `PA9 / PA10` | `USART0` + `CH340` | 固定复用 | 最适合做调试口、日志口、Bootloader 口 |
| `PA13 / PA14` | `SWDIO / SWCLK` | 必须保留 | 下载调试必需 |
| `PA15` | `FLASH_CS` | 固定复用 | 板载 SPI Flash 片选 |
| `PB2` | `BOOT1` | 谨慎使用 | 系统启动配置脚 |
| `PB3 / PB4 / PB5` | `SPI_SCK / MISO / MOSI` | 固定复用 | 板载 SPI Flash 总线 |
| `PB8 / PB9` | `OLED + 24C08` I2C | 固定复用 | 已有上拉，板载器件直接挂载 |
| `PC0` | 电位器 ADC | 固定复用 | 最方便的 ADC 演示与功能验证输入 |
| `PC2` | 外部基准参考 | 校准专用 | 接 `H7` 时用于 ADC 满度校准 |
| `PC14 / PC15` | RTC 晶振 | 必须保留 | RTC 正常运行依赖 |
| `PD3` | `PHY_RST` | 不建议占用 | 以太网 PHY 复位 |
| `PD5 / PD6` | `USART1_TX / RX` | 固定复用 | 通过 `H10` 连接 RS232 / RS485 |
| `PD8 / PD9` | `USART2_TX / RX` | 固定复用 | 通过 `H11` 连接 TTL / 扩展模块 |
| `PE8` | `485_CS` | 固定复用 | RS485 方向控制 |
| `PE9 / PE10` | 扩展板 SPI 片选 | 预留 | 后续通信板 / 传感板扩展 |
| `PE12 / PE13 / PE14` | `SPI3` 总线 | 优先预留 | 决赛外接 SPI ADC 最合适 |

### 5.2 可条件复用资源

下列引脚在某些板载功能不启用时，可以作为普通 IO 使用，但不建议优先选用：

| GPIO | 可复用前提 | 不优先选用原因 |
|---|---|---|
| `PB10 / PB11 / PB12 / PB13` | 不使用以太网 | 属于以太网发送路径，后续若启用网口会冲突 |
| `PC1 / PC4 / PC5` | PHY 复位或网口不启用 | 同样属于以太网路径 |
| `PC8 / PC9 / PC10 / PC11 / PC12 / PD2 / PE2` | 不使用 TF 卡 | SDIO 引脚多、带上拉，做普通 IO 维护成本高 |
| `PC6 / PC7` | 不接传感扩展板 | 已预留给扩展串口，留着更灵活 |
| `PE9 / PE10 / PE12 / PE13 / PE14` | 不接扩展 SPI 设备 | 未来扩展价值高，不适合拿去做基础键灯 |

## 6. 推荐引脚分配总表

### 6.1 核心功能分配

| 功能模块 | 推荐 GPIO | 资源归属 | 分配理由 |
|---|---|---|---|
| SWD 调试下载 | `PA13 / PA14` | 固定系统资源 | 必须全程保留，避免失去下载与单步调试能力 |
| 复位 | `NRST` | 固定系统资源 | 独立硬件复位链路，不能挪用 |
| Boot 配置 | `BOOT0 / PB2` | 固定系统资源 | 影响启动模式，原则上不参与业务规划 |
| 主调试串口 | `PA9 / PA10` | 板载 `CH340` | 上位机连接最直接，适合作为日志与命令接口 |
| 工业串口 | `PD5 / PD6` | `USART1` | 可在 `RS485 / RS232` 之间切换，适合现场通信 |
| RS485 方向控制 | `PE8` | 板载收发控制 | 板卡已明确此功能，复用最稳妥 |
| TTL 串口备用 | `PD8 / PD9` | `USART2` | 适合模块调试、双串口联调、备用数据口 |
| OLED 显示 | `PB8 / PB9` | I2C 总线 | 板卡已完成连接和上拉设计 |
| EEPROM 存储 | `PB8 / PB9` | 与 OLED 共线 | 共用 I2C 总线，节省 GPIO |
| 外部 Flash | `PA15 / PB3 / PB4 / PB5` | 板载 SPI Flash | 最适合参数持久化、日志、升级镜像 |
| ADC 主输入 | `PC0` | 板载电位器 | 样题阶段最容易演示采样结果 |
| ADC 校准输入 | `PC2` | `H7` 外部基准 | 用于校准与满量程检查，不建议长期业务占用 |
| DAC 输出 1 | `PA4` | MCU 原生 DAC | 标准 DAC 输出脚，应优先保留给模拟输出 |
| DAC 输出 2 | `PA5` | MCU 原生 DAC | 如需双通道 DAC，可同时启用 |
| 低功耗唤醒 | `PA0` | 板载唤醒按键 | 与待机唤醒场景天然匹配 |
| RTC | `PC14 / PC15` | 板载晶振 + 电池 | 板载资源已齐备，无需重新规划 |

### 6.2 用户按键推荐分配

建议将 `H3` 的 6 路用户按键统一分配到 `PD10 ~ PD15`。

| 用户按键 | 推荐 GPIO | 推荐用途 | 原因 |
|---|---|---|---|
| `KEY1` | `PD10` | 模式切换 | 空闲、干净、连续 |
| `KEY2` | `PD11` | 参数加 | 适合 EXTI 或扫描输入 |
| `KEY3` | `PD12` | 参数减 | 统一放在同一 GPIO 组便于管理 |
| `KEY4` | `PD13` | 确认 | 后续软件抽象简单 |
| `KEY5` | `PD14` | 返回 | 不占用关键外设 |
| `KEY6` | `PD15` | 自定义功能 | 便于扩展 |

选择 `PD10 ~ PD15` 的原因：

- 6 个引脚连续，便于统一初始化。
- 无板载硬性占用。
- 若后续需要中断输入，EXTI 管理清晰。
- 不影响串口、I2C、SPI、ADC、DAC 等核心功能。

### 6.3 用户 LED 推荐分配

建议将 `H4` 的 6 路用户 LED 统一分配到 `PE0 / PE1 / PE3 / PE4 / PE5 / PE6`。

| 用户 LED | 推荐 GPIO | 推荐用途 | 原因 |
|---|---|---|---|
| `LED1` | `PE0` | 电源后软件状态 | 空闲脚，适合作数字输出 |
| `LED2` | `PE1` | 模式指示 | 同组引脚，布局整齐 |
| `LED3` | `PE3` | 采样状态 | 避开 `PE2` 的 SD 卡检测 |
| `LED4` | `PE4` | 通信状态 | 输出控制简单稳定 |
| `LED5` | `PE5` | 告警状态 | 后续可拓展闪烁编码 |
| `LED6` | `PE6` | 用户自定义 | 与前 5 路统一管理 |

选择这组引脚的原因：

- `PE` 组上这几根线整体比较干净。
- 明确避开了 `PE2(SD_CD)` 和 `PE8/PE9/PE10/PE12/PE13/PE14` 这些扩展相关引脚。
- 适合后续用结构体、位掩码或数组集中管理。

## 7. 不建议沿用模板中的 LED 占用方式

当前模板工程里已经把 `PA4 ~ PA7` 用作 LED。

这只适合最小示例工程，不适合最终比赛方案，原因如下：

- `PA4 / PA5` 是最标准的 DAC 输出脚，最终应优先保留给模拟输出功能。
- `PA7` 与以太网 `ETH_CRS_DV` 相关，不属于理想的普通用户 LED 引脚。
- 若继续占用 `PA4 / PA5`，后续实现样题中的 DAC 功能时会发生结构性冲突。

因此建议把用户 LED 从 `PA4 ~ PA7` 迁出，统一改到 `PE` 组。

## 8. 跳线与硬件连接建议

### 8.1 必接或建议接通

| 跳线/接口 | 建议状态 | 用途 |
|---|---|---|
| `H1` | 接调试器 | SWD 下载与调试 |
| `H12` | 接通 `PA9 / PA10` 与 `CH340` | 主调试串口 |
| `H10` | 按需求选择 `RS485` 或 `RS232` | `USART1` 工业通信 |
| `H11` | 按需求选择 `TTL` 或通信扩展板 | `USART2` 备用串口 |
| `H3` | 将 6 路按键接到 `PD10 ~ PD15` | 用户按键输入 |
| `H4` | 将 6 路 LED 接到 `PE0 / PE1 / PE3 / PE4 / PE5 / PE6` | 用户 LED 输出 |

### 8.2 按需接通

| 跳线/接口 | 建议状态 | 说明 |
|---|---|---|
| `H7` | 校准时接通 | 将 `PC2` 接到外部基准参考，用于 ADC 满度校验 |
| 传感扩展板 SPI | 决赛阶段接入 | 使用 `SPI3` 与外接 ADC 或传感器通信 |

## 9. 决赛阶段外接 SPI ADC 预留方案

样题决赛要求外部 ADC 通过 SPI 与主控通信。

推荐预留：

- `PE12`：`SPI3_SCK`
- `PE13`：`SPI3_MISO`
- `PE14`：`SPI3_MOSI`
- `PE10`：外接 ADC 片选

理由：

- 与板载 SPI Flash 使用不同总线，互不影响。
- 板卡已经把通信/传感扩展的 SPI 放在这组引脚上，扩展路径清晰。
- 便于在初赛阶段保持主控功能稳定，在决赛阶段再接入外部采样板。

如果决赛需要多个 SPI 从设备，可继续考虑：

- `PE9`：第二片选
- `PE15`：通用控制或中断输入

## 11. 推荐实施顺序

如果按比赛开发节奏推进，建议按下面顺序接线和验证：

1. 保留 `SWD`、`Boot`、`RTC` 等系统资源不动。
2. 接通 `H12`，先使用 `PA9 / PA10` 打通串口日志。
3. 直接使用板载 `PB8 / PB9` 驱动 OLED 和 EEPROM。
4. 先用 `PC0` 完成 ADC 采样链路。
5. 再启用 `PA4 / PA5` 完成 DAC 输出。
6. 最后通过 `H3 / H4` 接入用户按键和用户 LED。
7. 决赛或扩展阶段再接入 `SPI3` 外部 ADC。

## 12. 最终结论

对这块开发板来说，最优方案不是从所有 GPIO 中“找空脚”，而是按资源性质分层规划：

- 第一层：保留系统关键脚
- 第二层：复用板载固定资源
- 第三层：把用户键灯集中映射到连续空闲 GPIO
- 第四层：为决赛扩展 SPI 外设预留独立总线

按这套方案执行后，能够同时满足：

- 初赛全部核心功能实现
- 后续 DAC 功能不被 LED 占用破坏
- 低功耗、RTC、Bootloader 具备实现基础
- 串口调试、RS485、TTL、OLED、外部 Flash 均可顺利复用
- 决赛外接 SPI ADC 仍有清晰、低冲突的接入路径
